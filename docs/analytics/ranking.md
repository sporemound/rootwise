# 0.5 Objective, Pareto, and Review Contract

0.5 consumes only a `COMPLETE` 0.4 analysis run and writes a new ranking database beside it. It
does not open the inventory or observed source paths. DuckDB materializes registered Polars frames;
Polars lazy expressions derive bounded directory features.

Objectives are independent minimization intervals: negative storage benefit, preservation risk,
uncertainty, and incoherence. A directory robustly dominates another only when its worst supported
value is no worse than the other's best supported value for every objective, with one strict
improvement. Overlapping intervals remain incomparable. Ranking occurs within explicit top-level
path and size-band cohorts.

Review priority is `impact × uncertainty × Pareto sensitivity`. It selects questions for a human;
it is not an importance score, archive approval, or execution instruction. Review output is bounded
to 1–1000 rows. 0.5 is fixture-tested but not performance-qualified for multi-million-row input.
